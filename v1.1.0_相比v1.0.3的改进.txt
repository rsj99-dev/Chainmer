Chainmer v1.1.0 相比 v1.0.3 的改进清单
（2026-11-18）

1. 新增 stage2 两段式检索
   - 第一段：k=3 精确词倒排召回 top-N 候选；
   - 第二段：仅对候选现场生成 Chainmer 链键（u64）与 Js 子序列键，复用 adaptive_core 判别
     （Jc + β·Js − λ·Jbg，外加 k-mer 兜底分）；
   - Chainmer 键不建全库倒排，主索引保持 k-mer 键表（约 3.7 MB）。

2. 默认键集加入密度混合通道（索引 v6 → v7）
   - 锚点对键 ∪ 两掩码间距键（111101110111 / 111011010010111，raw 与类别双轨）；
   - 置空 dense_masks 可还原 v1.0.x 键集做消融。

3. u64 键（stage2 内部）
   - 128 位键截断为 64 位，碰撞期望约 1e-7；
   - 峰值内存 272 MB → 147 MB。

4. 持久化预计算缓存（格式 S2C2）
   - 文件 <db>.stage2cache，magic S2C2 + 库长度 + mtime±2s 校验；
   - 命中时加载 0.08 s；输出与重新构建逐字节一致（MD5 相同）。

5. 新增 --threads 参数
   - 预计算与查询并行，默认 4 线程；单线程与多线程结果完全一致。

6. 新增实验方法 chainmer-class（仅 CLASS8 锚点对键）
   - 用于消融与低资源评估；质量 0.645 / 假阳性 21.2% / 漏检 18.7%，不建议单独使用。

7. 质量改进（14 家族树真值，n=156）
   - 召回：0.738 → 0.739（持平）
   - 假阳性：18.6% → 16.0%（降低 2.6 个百分点）
   - 漏检：1.9% → 0.6%（降低 1.3 个百分点）
   - 同口径对照：blastp k-mer 0.740 / 21.2% / 0%；DIAMOND 0.624 / 17.3% / 22.8%

8. 性能改进（710 条库，156 查询，单机实测）
   - v1.0.3 adaptive：811 s / 403 MB
   - v1.0.3 --native：5.10 s / 158 MB
   - v1.1.0 stage2：1.19 s（4 线程）/ 3.08 s（单线程）/ 147 MB
   - 同机对照：DIAMOND 2.2.8 为 0.38 / 0.59 s、211 MB；blastp 2.17 为 5.65 / 6.36 s、24 MB

9. 新增内部 API
   - chainmer_keys_vec / subset_keys_vec：升序去重 Vec 版，热路径免 BTreeSet 分配；
   - 键语义与顺序与 BTreeSet 版完全一致。

10. CLI 精简
   - 移除 index / search / adaptive 三个子命令（旧的全库链键倒排路径）；
   - 仅保留 seed、stage2、compare；库内 index/search 模块只供内部测试，不再作为 CLI 暴露。

11. 文档与工程
   - 版本统一 v1.1.0（Cargo.toml / CLI about / README / README_CN / CHANGELOG）；
   - 53 项测试全绿（lib 39 + integration 14）；
   - 明确“无向量加速”：全仓库为标量实现，-C target-cpu=native 实测零收益（1.23 s vs 1.23 s）。

说明：
- 质量口径为 14 家族基因对树真值（n=156），FP=旁系反超查询比例、FN=零共享直系比例；
- 性能为同一 710 条库、156 条查询、缓存命中条件，时间为 3 次中位、内存为峰值 RSS；
- BLAST+ / DIAMOND 为官方 SIMD 构建，Chainmer 为标量实现；
- 与 v1.0.3 相比，v1.1.0 的结构性变化是“Chainmer 键不落全库索引、改为候选现场生成”，
  因此索引不再随 Chainmer 键密度膨胀。
